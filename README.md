# Вишлист на новоселье

Откройте `index.html` в браузере, чтобы посмотреть шаблон. Пока оба поля в `config.js` пустые, кнопки работают в деморежиме. Брони видны внутри одной вкладки и сбрасываются при перезагрузке.

## Подставить свои подарки

Отредактируйте `gifts.js`. Каждый подарок получает уникальный `id` из строчных латинских букв, цифр и дефисов, до 64 символов. Сохраняйте ID при смене описания или ссылки, чтобы привязанная к нему бронь сохранилась. Новому подарку назначайте новый ID. Категория в поле `category` совпадает с ID из списка `categories`.

Ссылки в шаблоне ведут на поиск товаров. Подставьте ссылки на конкретные позиции и проверьте их перед рассылкой. Приветствие меняется в `index.html`.

Поле `image` у каждого подарка задаёт URL фотографии или путь к локальному файлу, например `images/kettle.jpg`. В шаблоне использованы фотографии похожих товаров с сайтов магазинов. Они загружаются с внешних адресов и могут отличаться от выбранной вами модели. При подготовке своего списка замените их фотографиями конкретных подарков. Если фото недоступно, карточка показывает эмодзи.

## Подключить общую бронь

После обновления до бронирования по категориям повторно выполните весь `supabase.sql` в SQL Editor. Существующие брони сохраняются. Если несколько старых броней попали в одну категорию, скрипт откатится без удаления данных — сначала согласуйте с гостями, какой вариант оставить.

Категории теперь обозначают альтернативы, например «Стаканы». У всех альтернатив в `gifts.js` одинаковое поле `category`. Добавляя товар, добавьте также его ID и категорию в список `wishlist_private.gifts` в SQL-скрипте и выполните скрипт. База допускает одну бронь на категорию. Для изменения выбора снимите текущую бронь.

1. Создайте проект на тарифе Free в [Supabase](https://supabase.com/dashboard).
2. Откройте **SQL Editor**, вставьте содержимое `supabase.sql` целиком и нажмите **Run**. Скрипт создаст таблицу в закрытой схеме и три операции для сайта.
3. В диалоге **Connect** или настройках API найдите **Project URL** и **Publishable key**. Вставьте их в `supabaseUrl` и `publishableKey` в `config.js`. Публичный ключ обычно начинается с `sb_publishable_`. Секретные ключи и пароль базы храните вне репозитория. [Ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys)
4. Загрузите файлы проекта в публичный репозиторий GitHub. В **Settings → Pages → Build and deployment** выберите **Deploy from a branch**, ветку `main` и папку `/(root)`. После публикации там появится ссылка на сайт. [Настройка GitHub Pages](https://docs.github.com/en/pages/quickstart)

## Проверить перед рассылкой

1. Откройте опубликованный сайт в двух независимых профилях браузера. Займите подарок в одном. Во втором должна появиться отметка «Занято» примерно за 12 секунд, пока вкладка активна.
2. Снимите бронь в первом профиле. Проверьте, что подарок снова можно занять во втором. Попробуйте занять один подарок почти одновременно в обоих профилях. Подтверждение должен получить один профиль.
3. Из России без VPN проверьте сайт на домашнем Wi‑Fi и мобильном интернете. В каждой сети проверьте загрузку карточек, чтение статусов, занятие и отмену.

## Управлять бронями

Гость снимает свою бронь в том же браузере, где её поставил. Если он очистил данные сайта, хозяин может удалить бронь в **SQL Editor** по ID из `gifts.js`. Например, для чайника:

```sql
delete from wishlist_private.bookings where gift_id = 'kettle';
```

Каталог и возможность занять подарок доступны любому посетителю страницы. В открытом API видны ID занятых подарков. Имя гостя не запрашивается. Право отмены подтверждает случайный секрет из браузера, в базе хранится его хеш.

При недоступном API каталог остаётся видимым, а действия с бронью отключаются до обновления статусов. Если Supabase приостановил бесплатный проект после низкой активности, откройте его панель и нажмите **Resume project**. [Как возобновить проект](https://supabase.com/docs/guides/platform/free-project-pausing)
