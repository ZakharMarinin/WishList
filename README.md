# Вишлист на новоселье

Откройте `index.html` в браузере, чтобы посмотреть шаблон. Пока оба поля в `config.js` пустые, кнопки работают в деморежиме. Брони видны внутри одной вкладки и сбрасываются при перезагрузке.

## Управление каталогом

Откройте [админку](https://zakharmarinin.github.io/WishList/admin.html), введите почту администратора и откройте ссылку из письма Supabase. Можно также ввести код, если он указан в письме. Доступ проверяется в базе по подтверждённому адресу из закрытой таблицы администраторов.

Добавляйте, редактируйте и убирайте товары в черновике. Для каждой карточки укажите HTTPS-ссылки на товар и фотографию. Категория объединяет альтернативы, из которых гости могут занять один вариант. Чтобы добавить категорию, заполните поле «Новая категория». Нажмите «Опубликовать изменения», когда черновик готов.

Каталог хранится в Supabase. Открытые страницы получают изменения примерно за 12 секунд. При одновременной публикации из двух вкладок база отклонит устаревший черновик. Скрытие забронированного товара сохраняет бронь его категории. Категорию забронированного товара можно изменить после снятия брони.

Кнопка «Проверить подборку Маркета» вызывает Edge Function market-import и показывает новые и удалённые позиции перед изменением черновика. Импорт принимает только полный структурированный список. Если Маркет блокирует серверный запрос или отдаёт неполные данные, каталог сохраняется, а интерфейс предлагает ручное добавление.

## Первоначальная настройка

1. Для нового проекта один раз выполните supabase.sql, затем admin-schema.sql в SQL Editor. Для уже настроенной базы с бронями выполните admin-schema.sql. Он переносит исходные 19 товаров при первом запуске. После перехода на админку обновляйте каталог через неё.
2. В config.js укажите Project URL и Publishable key Supabase. Секретные ключи хранятся в серверном окружении.
3. В Supabase Auth URL Configuration задайте Site URL https://zakharmarinin.github.io/WishList/admin.html. Для другого домена измените этот адрес и allowedOrigin в функции.
4. В Edge Functions создайте market-import из supabase/functions/market-import/index.ts. Отключите устаревшую проверку «Verify JWT with legacy secret». Функция проверяет токен и права администратора через защищённый RPC Supabase.
5. В закрытой таблице wishlist_private.admins должен быть подтверждённый email администратора. admin-schema.sql настраивает согласованный адрес. Встроенная почта Supabase отправляет письма только участникам команды проекта. Для других адресов нужен настроенный SMTP.
6. Опубликуйте файлы HTML, CSS и JavaScript в корне GitHub Pages. gifts.js используется для локального деморежима. Рабочая страница читает каталог из Supabase.

## Проверить перед рассылкой

1. Откройте опубликованный сайт в двух независимых профилях браузера. Займите подарок в одном. Во втором должна появиться отметка «Занято» примерно за 12 секунд, пока вкладка активна.
2. Снимите бронь в первом профиле. Проверьте, что подарок снова можно занять во втором. Попробуйте занять один подарок почти одновременно в обоих профилях. Подтверждение должен получить один профиль.
3. Из России без VPN проверьте сайт на домашнем Wi‑Fi и мобильном интернете. В каждой сети проверьте загрузку карточек, чтение статусов, занятие и отмену.

## Управлять бронями

Гость снимает свою бронь в том же браузере, где её поставил. Если он очистил данные сайта, хозяин может удалить бронь в **SQL Editor** по ID товара. Например, для белой сахарницы:

```sql
delete from wishlist_private.bookings where gift_id = 'ym-5129769206';
```

Каталог и возможность занять подарок доступны любому посетителю страницы. В открытом API видны ID занятых подарков. Имя гостя не запрашивается. Право отмены подтверждает случайный секрет из браузера, в базе хранится его хеш.

При недоступном API каталог остаётся видимым, а действия с бронью отключаются до обновления статусов. Если Supabase приостановил бесплатный проект после низкой активности, откройте его панель и нажмите **Resume project**. [Как возобновить проект](https://supabase.com/docs/guides/platform/free-project-pausing)
