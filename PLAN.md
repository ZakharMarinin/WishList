# План вишлиста на новоселье

## Что получат гости

- Одна ссылка на русскоязычную страницу с категориями «Кухня», «Для дома» и «Уют». В первой версии будут примеры подарков и ссылок на магазины.
- На карточке видны название, краткое описание, ссылка на магазин и кнопка «Занять». Занятый подарок остаётся в каталоге с отметкой «Занято». Имя гостя не запрашиваем.
- Предлагаемое правило отмены. Гость снимает свою бронь в том же браузере, а хозяин может снять любую бронь через панель Supabase.

## Дизайн

Страница выглядит как приглашение на новоселье. Слева в верхнем блоке — заголовок и короткое приветствие, справа — крупная иллюстрация приоткрытой двери. Под приглашением идут фильтры и карточки. На телефоне карточки выстраиваются в один столбец.

- Палитра. Глубокий синий `#132B50` для фона, светлый `#F2F5FB` для карточек, чернильный `#172743` для текста, жёлтый `#F6CF66` для основного действия, серо-синий `#526480` для вторичного текста.
- Типографика. Georgia для заголовков и системный шрифт для остального интерфейса. Странице не нужны запросы к сервисам шрифтов.
- Выравнивание слева. Статус «Занято» обозначается текстом. Для кнопок и ссылок предусмотрен видимый фокус с клавиатуры.

```text
┌─────────────────────────────────────────────────┐
│ Вишлист на новоселье         Приоткрытая дверь  │
│ Приветствие                                     │
├─────────────────────────────────────────────────┤
│ Все  |  Кухня  |  Для дома  |  Уют               │
│ [Подарок · Магазин · Занять] [Подарок · Занято]   │
└─────────────────────────────────────────────────┘
```

## Как работает бронь

1. GitHub Pages публикует HTML, CSS и JavaScript. Каталог лежит в `gifts.js`. У каждого подарка есть постоянный ID, который сохраняется при смене названия или ссылки.
2. SQL-скрипт создаёт в Supabase таблицу броней и операции чтения, занятия и отмены. Прямой доступ гостей к таблице закрыт. Чтение возвращает ID занятых подарков.
3. Нажатие «Занять» отправляет запрос в Supabase. База принимает максимум одну запись на подарок. При одновременных запросах второй гость получает «Уже занято». Интерфейс показывает успешную бронь после подтверждения базы.
4. Для отмены браузер сохраняет случайный секрет, а база хранит его хеш. После очистки данных браузера гость может обратиться к хозяину.
5. Страница обновляет статусы при открытии, после действий и периодически, пока вкладка видима. При сбое она показывает «Не удалось проверить брони» и даёт повторить запрос. Каталог остаётся доступен.

## Этапы работ

1. Собрать адаптивную страницу и шаблон каталога. Сделать фильтры и состояния карточек.
2. Подготовить SQL и подключить JavaScript к Supabase. В конфигурацию сайта входят адрес проекта и публичный ключ. Для локального предпросмотра без Supabase явно обозначить демонстрационный режим либо отключить общую бронь с пояснением.
3. Приложить инструкцию по редактированию каталога, настройке Supabase, публикации на GitHub Pages и возобновлению проекта после паузы.
4. Проверить мобильную и настольную вёрстку, навигацию с клавиатуры, сбой API и синхронизацию двух независимых браузеров. Проверить одновременную бронь одной позиции, запрет чужой отмены и появление статуса после повторного открытия страницы.
5. Перед рассылкой проверить опубликованную ссылку в России без VPN по домашнему Wi‑Fi и мобильной сети. В обеих сетях проверить открытие каталога, чтение статусов и запись брони. При проблемах определить, какой адрес недоступен, и выбрать замену для этого компонента.
